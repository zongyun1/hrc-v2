# Human motion：预训练推理备选路线

日期：2026-09-07。本文是 [总体 framework 方案](human_motion_framework_proposal.zh-CN.md) 的实验选型版，仅设计路线，尚未实施或验证效果。

**当前主线见 [面向 robot benchmark 的轻量升级方案](human_motion_benchmark_plan.zh-CN.md)，其中 B1–B3 不依赖预训练动作网络。** 本页仅保留全身物理控制的备选实验；下文的“首选”和顺序仅在此分支内有效，不代表当前整体优先级。

本备选分支约束：**全身物理人体与真实接触、优先 Isaac Lab，暂不进行任何新增训练。** 本页候选仅使用公开预训练权重，不 fine-tune、不训练任务 head/residual、不蒸馏。允许代码迁移、数据格式转换、参考轨迹几何修正和推理；若必须修改模型权重才能满足目标，暂停该项。

保留原编号，R1 已移除，R2 只作可选诊断，**R5 暂缓。首选 R3 的官方 teacher checkpoint + Isaac Lab 推理入口；R4、R6 仅作条件性备选，不承诺无训练即可在目标场景成功。** 本次只核查公开说明与入口，未下载验证权重完整性、安装依赖或运行仿真。

## 路线对比

| ID | 技术路线 | 核心输入 | 人体与接触方式 | 当前状态 | 最适合验证 |
| --- | --- | --- | --- | --- | --- |
| R3 | InterMimic 联合参考跟踪 | 人体 + 物体 + 接触参考 | 全身物理人体与动态物体 | 首选：冻结官方 checkpoint，先验证其样例 | 现有技能的物理执行与接触质量 |
| R4 | Omnigrasp 物体目标控制 | 物体几何、目标轨迹与当前状态 | 全身物理人体与灵巧手 | 备选：原生 Gym 可用发布权重；Lab 迁移待验证 | 指定物体怎么移动，让人物自行配合 |
| R6 | CHOIS/OMOMO + 手部细化 + 物理跟踪 | 语言/waypoints 或物体轨迹 | 生成联合参考，再由物理人体执行 | 条件性尝试：冻结两端模型，需 R3 已可靠执行 | 已有权重之间能否形成可执行参考链路 |

## Isaac Lab 支持与迁移范围

Isaac Lab 仍为目标执行平台，但“有预训练权重”与“在 Lab 中无需训练即可成功”需要分别验证。以下为官方文档核查结果。

| 路线 | 现成 Isaac Lab 支持 | 统一到 Isaac Lab 还需完成什么 |
| --- | --- | --- |
| R3 InterMimic | 有 teacher checkpoint 的 Lab 推理入口。[官方说明](https://github.com/Sirui-Xu/InterMimic) | 检查权重可获取、原生骨架/观测一致与实际接触质量；不迁移训练流程。 |
| R4 Omnigrasp | 官方发布权重与推理基于 Isaac Gym，未见官方 Lab 后端。[官方代码](https://github.com/ZhengyiLuo/Omnigrasp) | 仅迁移推理所需资产、关节/刚体索引、观测、动作时序、接触和重置。跨后端效果不达标时记录受限，不微调或重训。 |
| R6 生成参考 + 物理执行 | 生成器有预训练模型入口，在独立环境输出参考。[CHOIS 代码](https://github.com/lijiaman/chois_release) | 接到已通过验证的 Lab tracker；完成参考格式与手部适配。两端均冻结，无法执行的候选计为失败。 |

若所有实验都必须在 Isaac Lab 内执行，当前优先级为 R3 → 有条件的 R6；R4 作为单独的冻结权重迁移候选。若允许原生 Isaac Gym 对照，可直接先测 R4 发布模型，但这不是其 Lab 可用性的证明。当前工程使用 Lab 3 beta，InterMimic 推荐 Lab 2.3.1/Sim 5.1.0，仍需独立做版本与接触验证。

## R3：InterMimic——联合参考驱动的全身物理交互

**要回答的问题：给定可信的人—物演示，能否把它执行成自然、稳定、可受扰动的物理交互？**

[InterMimic，CVPR 2025](https://sirui-xu.github.io/InterMimic/) 提供人、物体与接触的联合跟踪方法；当前只使用作者已训练好的模型。[官方代码](https://github.com/Sirui-Xu/InterMimic) 明确提供一个 OMOMO teacher checkpoint 及样例，并有 Lab 推理脚本；不能据此认为已获得覆盖任意任务的全部 teacher。

```text
人体运动 + 物体轨迹 + 接触计划
    -> InterMimic policy
    -> 全身及手指 PD targets
    -> 人体、物体共同进行物理仿真
```

**先复用：** 官方人体、物体、样例 motion 和 teacher checkpoint。保留其动作维度、关节顺序、仿真参数和观测归一化；先查看实际物理执行，不把 data replay 当作 policy rollout。

**最小实验分三步：**

1. 在官方支持环境跑通一个原生样例，记录物体运动、接触、穿透和人体状态。
2. 使用同一物体和 reference，单独施加轻微物理扰动，检查恢复与失败；修改参考初始位置时，人与物体及接触 frame 一起变换。
3. 在发布模型已覆盖的技能附近尝试少量参考和目标变化，仅做冻结权重泛化测试。机器人交接另列为目标场景探测，不承诺 checkpoint 已学会接取、放手或长时间等待。

**权重与输入：** 首轮固定官方人体、样例物体、配对参考和权重，不更换手型或添加策略输入维度。数据转换只处理已有参考，不构造新的训练集。新物体、新技能超出能力时记为不支持，不通过 teacher training、fine-tune 或 student distillation 补齐。

**环境：** 官方 Lab 脚本为 `isaaclab/scripts/test_policy.sh`，示例使用 `checkpoints/smplx_teachers/sub2.pth`。README 对测试的描述是环境创建、观测维度和基础步进验证，因此仍须检查完整接触质量，不能把有入口视为 rollout 已可靠。数据回放也不等同于策略推理。

**看什么结果：** 完成度、物体与接触跟踪、脚滑、跌倒、手物穿透，及扰动后的重新稳定。作者在 [论文 Discussion](https://arxiv.org/html/2502.20390v2) 承认可能通过穿透支撑物体，所以“提起来”不是唯一验收条件。

**成本与边界：** 主要工作是环境、资产与推理验证，不包含训练。输入包含完整联合参考，评估时应标明这一信息优势。新物体不能随意替换 mesh 后沿用旧接触点；当前目标是测清发布模型的可用范围。

## R4：Omnigrasp——物体轨迹驱动的全身抓取

**要回答的问题：不提供完整的人体动作，只指定物体应该怎样移动，人物能否自己产生相应姿态并抓稳？**

[Omnigrasp，NeurIPS 2024](https://arxiv.org/html/2407.11385v2) 用运动先验和物体目标控制模拟人体抓取；[官方仓库](https://github.com/ZhengyiLuo/Omnigrasp) 已有推理、模型和训练入口。pre-grasp 用于训练奖励，推理策略不接收 grasp guidance 或完整人体参考；运动先验与训练仍使用人体数据。

```text
物体几何 + 当前人体/物体状态 + 未来物体目标轨迹
    -> grasp policy 在运动 latent 中决策
    -> PULSE-X 等先验解码全身动作
    -> 真实接触抓取并跟随物体目标
```

**最小实验：** 先用官方 GRAB 样例对象与 checkpoint 做原生推理，再让同一对象跟随“提起—横移—保持”的低速轨迹。随后增加轨迹变化和未见对象。目标只是 reference，物体实际位姿始终由接触推进。

**已有部分：** 官方抓取 policy、PULSE-X 先验权重和物体轨迹接口都保持冻结。机器人交接、特定抓取区域与释放动作暂不当作既有能力；可测试现有接口能表达的目标，但不增加需要训练的输入通道或策略模块。原模型的训练使用 pre-grasp 奖励，不表示推理也需要该输入。

**关键实验：** 先复现作者设置，再做“桌面和机器人碰撞体始终保留”的目标场景测试。论文部分实验在 1.5 秒后移除起始桌子；保留碰撞体后的结果作为冻结模型泛化测量，失败时不追加场景观测训练来补救。

**权重与平台：** 原生推理使用发布的任务模型与 PULSE-X，首轮保留其 Isaac Gym、SMPL-X 和样例依赖。迁移 Lab 属于后端适配实验，不能预先保证冻结权重仍然有效；若须训练才能恢复效果，则该迁移暂缓。

**看什么结果：** 抓取率、物体目标误差、滑移/穿透、是否撞桌、目标改变后的身体配合。与 R3 比较时注明：R4 推理不接收完整人体轨迹或 pre-grasp，但仍有物体未来轨迹、几何和当前模拟状态；训练数据依赖单独报告。

**成本与边界：** 原生验证中等，复杂场景扩展中高。很适合“让箱子/杯子移动到指定位置”的控制方式；门、抽屉、多次释放和机器人交接不能从原生持物跟踪能力直接推导。

## R5：暂缓，不列入当前实验

原 R5 需要新增接触 task policy/residual 训练，因此暂不考虑。ProtoMotions 的 [预训练模型目录](https://nvlabs.github.io/ProtoMotions/getting_started/pretrained_models.html) 虽有 SMPL MaskedMimic 的 Lab 推理权重，但它不是当前需求下现成的带手指 HOI 控制器。不能把基础走路/到达演示替代真实人—物交互；本阶段也不添加手指后再训练适配。

## R6：CHOIS/OMOMO 生成参考 + InterMimic 物理执行

**要回答的问题：是否能少写手工 motion，让同一任务产生多种可执行的全身交互？**

基于 [CHOIS](https://github.com/lijiaman/chois_release) 或 [OMOMO](https://lijiaman.github.io/projects/omomo/) 生成联合参考，必要时补手部，再通过 R3 的物理执行器。CHOIS 接受语言、初态和稀疏物体 waypoints；OMOMO 接受完整物体轨迹。首轮选其一，避免把两种输入条件混在一起。

```text
任务 + 初态 + 物体 waypoints/trajectory
    -> CHOIS 或 OMOMO
    -> 全身/物体参考 + 接触修正 + 手指补全
    -> 格式、骨架、时间与物体局部 frame 适配
    -> 固定的 InterMimic tracker
```

**最小实验：** 先在生成器与 tracker 都支持的对象和动作范围内，固定同一初态与终点，生成 10 条搬物候选；逐条物理执行。对照组是同一 tracker 执行 mocap/清理过的参考，其他条件不变。

**已有部分：** 生成器及 tracker 各自的模型与代码。**新增部分：** 联合表示适配、时间重采样、缺失手指补全、接触可行性筛查和跟踪失败反馈。CHOIS/OMOMO 缺少完整手指控制；把两份仓库装在一起并不形成可用 pipeline。本组合是拟做的系统实验，不声称论文已经发布其即插即用集成。

**权重与前置条件：** 必须先取得并验证两端公开 checkpoint；生成器与 tracker 全程冻结。优先使用与发布 tracker 相容的对象、骨架和技能，缺失手指只允许现成手型、已发布模型推理或几何修正。若生成分布超出 tracker 能力，拒绝/重采样或暂停本路线，不 fine-tune tracker，也不通过改写实际物体位姿配合动画。

**看什么结果：** 生成候选数量、筛除比例、候选到实际成功的比例、成功动作多样性、接触质量、离线生成与在线控制各自耗时。记录所有候选，不能只展示筛选后的成功视频。

**成本与边界：** 系统集成高；最好在 R3 稳定后进行。它主要验证参考生成与多样性，相对于 R3 并不是另一种低层接触控制器。若原参考可执行而生成参考普遍失败，应先处理参考质量/分布，不同时改动 tracker 来掩盖原因。

## 共用实验协议

每条路线分开报告两层结果：**作者原生设置的复现**与**本项目目标场景的适配**。先保持原生骨架/仿真器确认方法能工作，再统一目标场景；跨仿真器和不同身体模型的结果不能未经说明排成同一性能榜。

### 目标场景与顺序

| 测试 | 任务 | 主要路线 |
| --- | --- | --- |
| E1 | 发布模型已有的拿起、持有或搬运任务；若支持释放，再验证放回 | R3 首选；R4 平台对照；R6 随 tracker |
| E2 | 原生样例附近改变位置、质量、摩擦或物体轨迹，测量泛化 | R3/R4，均保持权重冻结 |
| E3 | 同一目标的 mocap 参考与生成参考对比 | R6，仅在两端兼容且 R3 已通过后 |
| 目标探测 | 机器人交接、独立释放、长时间等待及新物体 | 只有现有 checkpoint/接口能表达时才测；不足时报告不支持 |

首轮使用 checkpoint 对应的官方对象。当前 5.5 cm、100 g 方块只可作为后续新对象探测，不能为匹配当前 demo 而强行更换模型资产或假定权重已支持。门、抽屉、刀、布料不纳入首轮。

调试采用 1 个原生样例 → 10 次小范围变化 → 稳定后 100 个固定初始化。位置偏移 ±5 cm、质量 0.5/1/2 倍、摩擦变化和交接延迟可作为初始扰动范围建议；先单因素，再组合。任何超出资产/方法可用范围的配置需要说明。

### 每次都记录的字段

| 类别 | 内容 |
| --- | --- |
| 条件 | route、代码/checkpoint 及文件 hash、backend、骨架、物体、seed、原模型训练来源、推理输入信息、模型权重是否保持不变 |
| 物理模式 | 主实验为 `floating_root_physical`；标明接触与碰撞设置，可选固定根诊断单独记录 |
| 任务 | 成功、各阶段完成时间、持有时长、掉落、重试、超时 |
| 接触 | 穿透深度/持续时间、滑移、接触与力数据的可用性、释放后的响应 |
| 人体 | 脚滑、跌倒、关节/力矩限制、动作连续性 |
| 成本 | 离线生成时间、在线控制延迟、推理 GPU 小时、显存和仿真吞吐；新增训练为零 |

“成功”需满足任务谓词，同时没有残留吸附、严重穿透或隐藏支撑。所有主路线使用全身物理执行，不逐帧写物体 pose，不回退到旧 spring grasp。密集参考路线与稀疏目标路线需要同时比较数据准备成本和输入信息，不能只看成功率。

## 推荐试验安排与保留候选

| 优先级 | 动作 | 决策价值 |
| --- | --- | --- |
| 第一组 | R3 官方 teacher checkpoint + 对应样例的 Lab 推理 | 核实最接近“无需训练 + Lab + 全身 HOI”的公开入口。 |
| 第二组 | R3 冻结模型的 E2；R4 原生 Gym 对照或独立 Lab 推理迁移 | 测清现有能力和跨后端限制，不增加训练补齐能力。 |
| 第三组 | 有条件的 R6：冻结生成器 + 已验证 tracker | 测量参考兼容性和多样性；不相容则暂停。 |

[InterPrior](https://sirui-xu.github.io/InterPrior/) 与 [SkillMimic-V2](https://github.com/Ingrid789/SkillMimic-V2) 只保留为文献候选。本次未核到前者的官方代码入口，后者 household 运行说明尚不完整，均不纳入本期预训练推理实验。

当前选型：R3 为首选；R4 是有公开权重但 Lab 兼容待验证的备选；R6 是依赖 R3 可用范围的冻结模型组合实验；R5 暂缓。现有 checkpoint 在厨房/仓储真实交接中的能力属于待测结果，不承诺完整新 framework 能在不训练的前提下覆盖所有任务。

## 可选局部诊断：原 R2，不作为升级路线

仅在需要区分“手部资产/接触参数错误”与“全身策略错误”时，可固定新人体的躯干，用 [GRAB](https://grab.is.tue.mpg.de/) / [GOAL](https://goal.is.tue.mpg.de/) 抓姿和有限力矩 PD 检查单物体抓取。保持真实指尖接触，禁用物体吸附；改变质量、摩擦和 PD 参数定位问题。诊断完成后回到自由根全身模型。该实验无需作为 R3–R6 的前置工作，其结果不计入主路线成功率。
