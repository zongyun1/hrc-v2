# Human motion：面向 robot benchmark 的轻量升级方案

更新日期：2026-09-07。只做方案与文献核查，尚未实现或运行实验。

2026-09-09 补充：[TRUMANS](https://jnnan.github.io/trumans/) 纳入 B1 的 motion 数据来源；接入步骤与首次实验见 [D1 技术路线](../docs/human_motion_technical_routes.zh-CN.md#d1trumans-作为-motion-来源)。当前使用记录片段的方案无需生成网络，预训练生成另作可选扩展。

新增 [基于公开代码的 C1–C5 实验路线](../docs/human_motion_technical_routes.zh-CN.md)：Human-Robot Gym、Habitat 3.0、HandoverSim/GenH2R、普通 Motion Matching 与 Environment-aware Motion Matching。每条列出可复用模块、现有接触简化、Isaac Lab 适配范围和首次实验；另附接触区域重定向代码。

## 1. 目标与选型

Human 是影响 robot 表现的交互变量。优先级为：动作自然、任务相关的多样性、交互条件可控、评测可信、实现成本可接受。本期无需训练，也不要求使用预训练动作网络；Isaac Lab 是目标执行平台。

**推荐主线：真实人—物动作库 → 按任务检索片段 → 接触约束下的目标适配 → 简单交互状态机 → 局部物理手与动态物体。** 身体行走、转身、姿态主要由动画驱动，不再把自由根人体平衡、全身力矩控制和抗跌倒作为前置工作。

此前“全新升级必须采用全身物理人体”的假设过重，现已取消。这里的升级落实到动作组织、目标适配、交互反馈和 benchmark 控制接口。动画与 IK 仍可使用，但只换更多动画或只调整持物弹簧不足以满足目标。

这属于非学习的动画与反馈系统。它仍使用骨架、几何和仿真模型；不将其笼统称为完全 model-free。此前的全身预训练控制路线保留在 [备选路线资料](human_motion_experiment_routes.zh-CN.md)，不作为当前第一优先级。

## 2. 已有工作怎样支持这个方向

| 来源 | 可以复用的思路 | 需要自行补齐的部分 |
| --- | --- | --- |
| [HandoverSim，ICRA 2022](https://handover-sim.github.io/)；[论文](https://handover-sim.github.io/assets/chao_icra2022.pdf) | 使用 DexYCB 记录的人手与物体轨迹构造 robot 接取评测；由实际机器人接触触发物体释放。 | 主要是手部与单向交接，human 轨迹反馈有限。其物体有辅助驱动且关闭人手—物体碰撞，不能当作真实指尖摩擦抓持。 |
| [GRAB，ECCV 2020](https://grab.is.tue.mpg.de/)；[数据代码](https://github.com/otaheri/GRAB) | 全身、手指、物体运动与接触信息，适合作为拿取、持有和递物的动作来源。直接读取记录不需要训练 GrabNet。 | 几何接触标签不是力测量；人与机器人协调需另设规则，动作与手型需要重定向。 |
| [Motion Matching 官方说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/motion-matching-in-unreal-engine) | 根据当前姿态、速度与目标轨迹检索动作；普通数据库搜索不需要神经网络。 | 官方示例侧重 locomotion。持物接触的筛选、手物相对特征和 Isaac Lab 接入是本方案设计，非现成官方功能。 |
| [Daniel Holden 的动作适配与脚锁定实现](https://theorangeduck.com/page/code-vs-data-driven-displacement) | 限幅修正根位移、平滑切换、接触期间锁脚并做 IK，兼顾参考风格与目标位置。 | 这些技术改善运动学连续性，不提供人体动力学平衡或物体抓取保证。 |
| [Isaac Lab actuators](https://isaac-sim.github.io/IsaacLab/main/source/overview/core-concepts/actuators.html) | 现有驱动器可将关节目标变为物理执行；可用于局部手臂/手指。 | 手资产、碰撞形状、驱动力上限和参考适配仍需集成、调参。不是即插即用的 human framework。 |

HandoverSim 说明“评测 robot”可以采用简化的人类执行模型。它也给出应保留的边界：视觉抓姿逼真，不代表人类抓握物理真实。借鉴该工作不意味着直接移植其全部接触简化。

## 3. 三条可分别尝试的动作路线

以下是动作产生方式的候选，共用交互状态机和接触执行层。先比较动作层时固定后两层，避免同时更换多个因素。

### B1：真实交互片段 + 接触约束变形，首选

从少量质量较高的完整交互动作开始，每条保存身体、手指、物体参考、接触区域及动作阶段。按物体类别、左右手、接触类型和目标位置选择相近片段，再做有限的站位、方向和时长调整。

动作来源加入 **TRUMANS（D1）**：优先筛选与当前室内任务匹配、人体与物体参考完整的片段；经骨架重定向和手物对齐验证后入库。数据中的动作标注还需映射为本项目交互阶段，目标交接动作的覆盖情况待检查。

适配时联合处理躯干、肩肘、手腕、手指和支撑脚。持物段以物体局部接触区域为参照；物体实际偏离参考时，只在可达范围内调整人手目标，超过范围则等待、重选片段或失败。物体参考轨迹不直接覆盖仿真中的物体状态。

动作按 approach / contact / present / wait / release / retreat 分段。等待时进入自然的短循环；确认接触或超时后才切到下一段。持物阶段禁止跨不相容抓姿随意混合。

**最小实验：** 先选约 10–20 条合适片段作为数据准备目标，覆盖伸手、递物、等待与撤回；具体数量取决于数据质量，不是方法要求。固定简单物体，测试多个交接位置和机器人快慢变化。

**优点：** 自然度主要来自真实记录；无需训练；先做片段级检索即可，开发范围较小。**限制：** 新任务依赖数据覆盖，过大变形会损坏动作；骨架和手部重定向是主要成本。建议先固定一种人体骨架和一种抓握类型。

### B2：接触感知的 Motion Matching，动作衔接的升级候选

检索不只看任务标签，还比较当前身体姿态/速度、未来行走方向、手腕相对物体的位置与方向、左右手占用及接触阶段。先按阶段和抓握类型过滤，再搜索相近动作，使用平滑过渡接续。

**最小实验：** 使用与 B1 相同的动作库和接触层，让 robot 迟到、暂停或改变交接点，比较动作切换跳变、重复感与有效覆盖。先允许走路和空手段切换；持物段只在接触相容的边界切换。

**优点：** 更适合连续走近、转向、等待、再次伸手，能减少逐条编写过渡。**限制：** 需要动作库覆盖与特征调参，不会凭空创造新技能，也不自动解决真实抓握。只有 B1 的衔接与覆盖成为瓶颈时才值得增加这层复杂度。

### B3：参数化动作模板 + IK，补充路线

用少量姿态和手腕路径定义伸手、让路、后退、指向等动作，配合躯干倾斜、视线和自然待机片段；通过样条与时间曲线控制速度，IK 处理可达目标。

**最小实验：** 与 B1 保持相同目标和时长，比较同一个 reach / wait / retreat 的自然度、穿透和数据准备成本。

**优点：** 数据需求较低、参数明确，适合精确生成干扰和反应行为。**限制：** 手工设计协调动作需要时间，复杂拿取和搬运容易显得机械。它与旧框架的动画/IK 思路重叠最多，因此只作补充，不单独作为“全新升级”的主方案。

## 4. 身体简化，接触保留到什么程度

推荐将物理复杂度集中在 robot 实际交互的区域：

```text
动作库/检索 ──> 全身参考 ──> 身体蒙皮与碰撞表示
                       └─> 手臂/手指目标 ──> 受限驱动的局部物理手
                                              ↕ 接触
robot policy ──> 物理 robot ────────────────> 动态物体
                                              ↓
                                 接触事件、等待、释放与评测
```

身体及站位可以由运动学参考驱动；前臂/手部采用局部 articulation，基座由身体参考提供，手指通过有限驱动接触物体。若采用独立动态手掌，参考跟踪的最大作用力/力矩也须受限。渲染手指跟随实际局部物理姿态，避免可见手与碰撞手分离。物体保持动态，由接触推动。

这省去了全身平衡控制，但**手部资产和接触调参仍是本方案最大的工程不确定项**。首轮只做一种简单抓握；先证明所选手型能稳定保持并释放目标物体，再增加外观和任务。它不是完整人体受力模型，不能用来评价人体被推倒或负重步态。

如果局部物理手成本仍过高，可另设 **HandoverSim 式持物代理对照**：用显式、有限的物体驱动近似 human 持物，并在交接时撤除。[其物体驱动与释放实现](https://github.com/NVlabs/handover-sim/blob/master/handover/ycb.py) 可供参考。这与当前厨房的弹簧持物已有重叠，所以不作为主要接触升级，也不能称为真实人手抓握。代理与物理手的结果分开报告，不在失败时静默切换。

若 human 只作遮挡和非接触干扰，动画与几何碰撞表示已经足够；若测 robot 的接取、推物或共享接触，则启用对应的接触执行层。人体碰撞代理的接触力不能直接解释为真实人体伤害程度。

## 5. 真正影响 robot 的 diversity

| 变量 | 测试 robot 的能力 | 生成方式与边界 |
| --- | --- | --- |
| 交接位置、方向、站位 | 可达性、抓取位姿适应 | 原片段采样 + 限幅变形，检查人体可达和环境碰撞 |
| 左右手、握持区域、遮挡 | 找到剩余可抓区域、视觉鲁棒性 | 使用对应记录；镜像同时处理人体、物体与接触，非对称物体需重新验证 |
| 速度、停顿、释放延迟 | 时序协调、等待能力 | 有界时间变形 + 事件驱动的自然等待，不在接触冲击附近任意变速 |
| 配合、迟疑、撤回、换目标 | 重规划与失败恢复 | 固定行为规则及反应延迟，撤回作为单独任务条件，不混入正常交接成功率 |
| 经过、转身、伸手遮挡 | 人体避碰与动态视觉干扰 | 合理的空间路径和片段组合，记录最小距离与遮挡比例 |
| 身体比例与动作风格 | 跨人的适应能力 | 多来源/多表演者片段；仅换外观不能算运动多样性 |

不要给每个关节独立加随机噪声制造 diversity。采样有意义的行为条件，保持身体、手指和物体参考的一致性，并保存每个 episode 的完整配置。

## 6. 交接与评测规则

Human 可以读取环境状态执行有限的等待、让位和释放规则。规则、反应时延和阈值对所有 robot 方法相同，不读取 robot 方法身份或未执行的未来动作。机器人可见的观测另行固定，不默认暴露 human 的未来轨迹与内部阶段。

human → robot：接近并呈递 → 等待有效 robot 接触 → 人手逐渐卸载/张开 → 确认 human 支撑消失 → robot 独立持稳并搬离。对双指夹爪，双侧接触可作候选证据，但还需释放后的稳定持有；吸盘等末端使用相应判据，不能照搬双指规则。[HandoverSim 的接触与释放实现](https://github.com/NVlabs/handover-sim/blob/master/handover/handover_env.py) 以及 [释放后的成功判定](https://github.com/NVlabs/handover-sim/blob/master/handover/benchmark_wrapper.py) 是参考。

robot → human 另设接收协议及指标。人体脚本没有及时接好也可能造成失败，需记录失败发生在人体目标生成、接触执行还是机器人动作，避免把所有故障归给 robot。明确的人体非配合情形属于测试条件；生成错误和仿真错误属于基础设施问题，按预先确定的规则单列，不能事后挑选容易成功的 episode。

## 7. 如何证明比旧版好

只升级 framework 的名称不能证明效果。建议用同一机器人、相近任务和同一评测协议比较：

1. **自然度：** 隐去方法标识的视频配对评价；同时测脚滑、腕部/身体跳变、穿透和不合理停顿。平滑度不能单独代表自然度。
2. **多样性：** 统计独立源动作/表演者、任务条件覆盖和有效动作比例；同一 clip 的多次变速单列为参数变化。
3. **交互能力：** robot 延迟、停顿、目标小幅变化时，human 能否合理等待、重新伸手和释放。
4. **robot 评测有效性：** 按握持区域、速度、遮挡和反应类型分组报告成功、掉落、碰人、超时与恢复；成功必须包含 human 卸载后的物体状态。
5. **实现与运行成本：** 数据清理/重定向工时、每新增动作的准备成本、控制耗时和环境吞吐；本期训练成本为零。

固定测试配置，区分用于调参的动作与留出的独立片段/表演者；不同 robot 使用同一批行为配置，反馈 human 的实际轨迹允许因机器人动作不同而变化。保存实际轨迹用于复查，固定 seed 不代表 GPU 仿真跨版本逐位一致。

建议顺序为：**B1 + 一种局部物理抓握 → 验证等待/释放 → 扩展任务相关变量 → 需要时加入 B2；B3 用于补齐干扰与反应。** 全身 RL、MPC、逆动力学人体控制与大型生成模型暂不作为主线依赖。
