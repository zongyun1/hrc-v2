# HARPv2

Human-present mobile manipulation in [Genesis](https://github.com/Genesis-Embodied-AI/Genesis):
RoboCasa kitchens, a physically-present human driven by a motion diffusion model, and a
robot doing manipulation in the same scene at the same time.

Status and results live in [`docs/progress.md`](docs/progress.md); the plan is in
[`human-present-mobile-manipulation-plan.md`](human-present-mobile-manipulation-plan.md).

---

## Layout

```
hpmm/
├── hpmm_motion/          simulator-agnostic human motion. Never imports Genesis.
│   └── io/schema.py      ★ the frozen contract between the two layers
├── hpmm_sim/             Genesis side
│   ├── assets/           MJCF loading (load.py) and repair (convert.py)
│   ├── human/            skeleton.py (capsules), skin.py (surface), driver.py
│   ├── robot/            PandaOmron dof bookkeeping
│   ├── shim/             replaying robosuite's sampler output into Genesis
│   └── vis/              camera placement inside sealed rooms
├── assets/               ★ body-model assets — NOT in git, see below
└── tests/                pytest: invariants and regressions
tools/                    pipeline stages and verification harnesses
exports/                  ★ derived output — NOT in git
```

Two directories are deliberately untracked, for different reasons: `exports/` because
everything in it is regenerated by something in `tools/`, and `hpmm/assets/` because of the
licence discussed below.

## Environments

Three venvs, because the dependencies genuinely conflict. Nothing imports across them; they
communicate through files.

| venv | Python | for |
|---|---|---|
| `genesis/.venv` (uv) | 3.12 | Genesis, simulation, rendering |
| `third_party/trumans-venv` | 3.10 | TRUMANS motion diffusion, `smplx` |
| `third_party/robocasa-venv` | 3.11 | robosuite + robocasa, scene and task export |

```bash
# Genesis-side tools: run from genesis/ so uv picks up its venv. They put hpmm/ on
# sys.path themselves, so no PYTHONPATH is needed.
cd genesis && uv run python ../tools/<script>.py

# pytest does need it, since hpmm is not installed as a package
cd genesis && PYTHONPATH=../hpmm uv run python -m pytest ../hpmm/tests -q
```

## Body-model assets

`hpmm/assets/` holds two files distilled from a SMPL-X body model. **They are not
committed**: they are derived data (rest joint positions, vertex positions, skinning
weights), which inherits the model's research-only licence, so each user regenerates them
from their own copy of the model rather than receiving a redistribution.

| file | contents | consumed by |
|---|---|---|
| `smplx_skeleton_male.json` | 22 joints, parents, parent-relative rest offsets, one capsule per bone (`from`/`to`/`radius`), gender, height | `HumanSkeleton.from_template()` |
| `smplx_skin_male.npz` | `rest_verts` (V,3), `faces` (F,3), `rest_joints` (22,3), `weight_idx` (V,k) int16, `weight_val` (V,k) | `HumanSkin.from_asset()` |

Nothing else in the repo reads them, and both loaders fail with a message naming the
command below rather than a bare `FileNotFoundError`. Tests that need them **skip**, so a
fresh clone still runs its suite (14 pass, 11 skip).

### Regenerating

Needs `smplx` and a SMPL-X model file. The TRUMANS venv already has both — its bundle ships
`third_party/trumans_utils/smpl_models/smplx/SMPLX_MALE.npz`.

```bash
cd third_party/trumans_utils
../trumans-venv/bin/python ../../tools/extract_smplx_skeleton.py
```

Both files are written in one pass. Expect `26 bones, 22 joints, rest height 1.794 m` and
`10475 verts, 20908 faces, top-4 weights`.

### Using a different body model

```bash
cd third_party/trumans_utils
../trumans-venv/bin/python ../../tools/extract_smplx_skeleton.py \
    --model_path ./smpl_models --gender female \
    --out      ../../hpmm/assets/smplx_skeleton_female.json \
    --skin_out ../../hpmm/assets/smplx_skin_female.npz
```

Then point the driver at them — paths are parameters, not constants:

```python
from hpmm_sim.human.driver import HumanDriver
from hpmm_sim.human.skeleton import HumanSkeleton

human = HumanDriver(
    scene,
    skeleton=HumanSkeleton.from_template("hpmm/assets/smplx_skeleton_female.json"),
    skin="hpmm/assets/smplx_skin_female.npz",
)
```

Four things to know before swapping models:

1. **The skeleton and the skin must come from the same model.** The skin's weights index the
   skeleton's joints. `HumanDriver.bind()` checks the vertex count, which catches a
   decimated mesh but *not* a mismatched body — that failure is silent and looks like bad
   skinning.
2. **The joint tree must match the schema.** `hpmm_motion/io/schema.py` fixes
   `BODY_JOINT_NAMES` and `BODY_JOINT_PARENTS` (SMPL-X's 22 body joints), and the extractor
   asserts the model agrees. SMPL and SMPL-H share those first 22 joints and work as-is.
   A model with a different tree means editing those constants, which is a breaking change
   to the contract — bump `SCHEMA_VERSION`.
3. **Shape is baked in at `betas = 0`,** the model's mean body. A different body shape needs
   its own pair of files; the rest offsets and rest vertices both change.
4. **Motion must be generated against the same model.** `MotionSequence.gender` records
   which one; the pose parameters are meaningless against a different skeleton.

Nothing is hand-tuned in these files. Capsule radii come from the model's own LBS weights
(75th percentile perpendicular distance to the bone axis), and capsule density is solved
backwards from a 70 kg target because the capsules overlap and over-count volume ~5.2x. Both
therefore adapt to whatever model you feed in.

## Pipeline

Each stage writes into `exports/`. Later stages read those files, so run them in order the
first time. Scene builds are slow — convex decomposition takes minutes for a fresh RoboCasa
layout — but Genesis caches by content, so re-runs are fast.

**1 — Scene and task, in the robocasa venv** (from the repo root):

```bash
third_party/robocasa-venv/bin/python tools/export_robocasa_mjcf.py --layout 1 --style 1
third_party/robocasa-venv/bin/python tools/export_robocasa_task.py \
    --task PickPlaceCounterToCabinet --layout 1 --style 1 --seed 0
```

The base `Kitchen` env is an empty shell; a **task** env is what carries manipulable
objects. Object poses are sampled at `reset()` and are not in the XML, so the task exporter
writes the post-reset configuration alongside it, keyed by joint name.

**2 — Occupancy for the motion model, in the Genesis venv:**

```bash
cd genesis && uv run python ../tools/voxelize_kitchen_for_trumans.py \
    --mjcf ../exports/robocasa_layout1_style1.xml
```

Writes the occupancy grid into TRUMANS's `Scene/` and `exports/kitchen_transform.json`,
which records the frame change every later stage inverts.

**3 — Human motion, in the TRUMANS venv:**

```bash
cd third_party/trumans_utils
../trumans-venv/bin/python ../../tools/export_trumans_motion.py
```

Produces a schema-conformant `exports/motion_kitchen_walk.npz`. The sampler is stochastic
and roughly 40% of draws are degenerate (the body crouches and floats), so the exporter
gates on grounding quality and retries; `tools/probe_trumans_variance.py` is what measured
that rate.

**4 — Demonstrations, in the Genesis venv** (download once, per task):

```bash
third_party/robocasa-venv/bin/python \
    third_party/robocasa/robocasa/scripts/download_datasets.py \
    --tasks PickPlaceCounterToCabinet --source human --split pretrain
cd genesis && uv run python ../tools/import_robocasa_demo.py --episode 0
```

**5 — Run it, in the Genesis venv:**

```bash
cd genesis
uv run python ../tools/replay_demo_ik.py    --video ../exports/demo_ik.mp4
uv run python ../tools/phase1_cosim_demo.py
uv run python ../tools/verify_human_bridge.py --kitchen
uv run python ../tools/verify_task_instance.py
```

`verify_*` are verification harnesses: they need a GPU and a built scene, and they print
measurements rather than asserting. `hpmm/tests/` is the pytest suite.

## Working notes

Things that cost real time and give no error message when they go wrong. Each has a
regression test.

- **Load MJCF only through `hpmm_sim/assets/load.py`.** Genesis's `align` option defaults to
  `None`, which behaves like `True` and re-frames free bodies onto their centre of mass, so
  objects land displaced by their own `body_ipos` — small enough to read as noise, large
  enough to aim a grasp at the wrong place.
- **Index motion by elapsed time, not by step** (`HumanDriver.set_time`). Motion fps and
  solver `dt` are different numbers; one frame per step plays the human at `fps * dt` times
  real speed, which looks fine on video and corrupts every contact and approach metric.
- **Look at a frame before trusting a video.** RoboCasa rooms are sealed boxes with no
  ceiling; a camera placed by offsetting from its subject renders the outside of a wall,
  while every metric stays correct because they come from state queries. Use
  `hpmm_sim/vis/camera.py`.
- **Run one Genesis process at a time.** A second concurrent job falls back to software
  rendering and one of the two dies silently — and a shell pipeline ending in `| tail`
  reports `tail`'s exit code, so the failure looks like success.
