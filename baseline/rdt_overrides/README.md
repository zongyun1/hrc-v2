# RDT submodule overrides for genesis-hr-bench

The `baseline/rdt/` submodule tracks upstream `thu-ml/RoboticsDiffusionTransformer`, which we don't control. Files in this directory are copied **on top of** the submodule by `scripts/finetune_rdt.sh` before each training run, replacing the bimanual-ALOHA template files with the genesis-hr-bench schema (single Franka arm, 8-D state/action, 2 cameras, `instruction.json`) and fixing upstream bugs we hit at our run lengths.

Files mirror the submodule path:

| Override | Replaces in submodule | Reason |
|---|---|---|
| `data/hdf5_vla_dataset.py` | `baseline/rdt/data/hdf5_vla_dataset.py` | Schema rewrite: 8-D qpos/action, `cam_high` + `cam_right_wrist`, `instruction.json`, `RDT_HDF5_DIR` env var, unified-vec slots = `right_arm_joint_{0..6}_pos` + `right_gripper_open` |
| `configs/finetune_datasets.json` | same | Use `genesis_hr_bench` as the sole training dataset |
| `configs/finetune_sample_weights.json` | same | Sample weight 100 for `genesis_hr_bench` |
| `configs/dataset_control_freq.json` | same | Register `genesis_hr_bench` at 20 Hz |
| `train/train.py` | same | Flip `persistent_workers=True` → `False` on both DataLoaders. Bounds per-worker memory growth from `imgaug==0.4.0`'s stochastic-kernel caches, which OOM-killed a prior run at MaxRSS=1925 GiB after ~14 000 steps. |

`configs/dataset_stat.json` is **not** shipped — it gets regenerated by `python -m data.compute_dataset_stat_hdf5 --skip_exist` at the start of every finetune (idempotent; subsequent runs no-op once the entry exists).

The schema is set by the converter (`scripts/convert_genesis_hr_bench_to_rdt_hdf5.py`); keep override and converter in sync.
